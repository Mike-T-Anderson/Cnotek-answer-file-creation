The pipeline

    

      autounattend.xml → Packer installs + provisions over WinRM →
      sysprep /generalize /oobe /shutdown → golden VHDX →
      clone in Hyper-V → Jenkins: rename + domain join over WinRM
    

    
Two answer files are involved: the install-time file this tool generates (used once, when Packer installs Windows)
    and a small deploy-time file handed to sysprep (used by every clone to skip OOBE). Identity — name, domain, IP —
    belongs to the deployment job, never to the image.


    
1 Generate autounattend.xml

    
    
      
  • Click ⚡ Packer golden-image preset — random computer name, no domain join or static IP, auto-logon ×1, WinRM bootstrap, UEFI/GPT for a Hyper-V Gen 2 VM (use BIOS/MBR for Gen 1).
    • 
      
  • Set the Administrator password — this becomes Packer's winrm_password.
    • 
      
  • Pick version and edition; tick Evaluation Center media if building from an eval ISO (eval images are named "… Standard Evaluation …" and the name must match exactly).
    • 
      
  • Download as autounattend.xml.
    • 
    

    
Auto-logon ×1 is what fires the first-logon WinRM bootstrap headlessly. The count is consumed during the build, so clones boot to a normal locked logon screen.


    
2 Create deploy-unattend.xml (for sysprep)

    
Generalizing wipes OOBE state and the admin password. Without this file every clone stops at the console asking for
    region, EULA and a new Administrator password — and Jenkins can never connect. Save this next to your Packer template
    and replace the password/locale values:

    

      

<?xml version="1.0" encoding="utf-8"?>
<unattend xmlns="urn:schemas-microsoft-com:unattend">
    <settings pass="oobeSystem">
        <component name="Microsoft-Windows-International-Core" processorArchitecture="amd64" publicKeyToken="31bf3856ad364e35" language="neutral" versionScope="nonSxS" xmlns:wcm="http://schemas.microsoft.com/WMIConfig/2002/State">
            <InputLocale>en-AU</InputLocale>
            <SystemLocale>en-AU</SystemLocale>
            <UILanguage>en-US</UILanguage>
            <UserLocale>en-AU</UserLocale>
        </component>
        <component name="Microsoft-Windows-Shell-Setup" processorArchitecture="amd64" publicKeyToken="31bf3856ad364e35" language="neutral" versionScope="nonSxS" xmlns:wcm="http://schemas.microsoft.com/WMIConfig/2002/State">
            <OOBE>
                <HideEULAPage>true</HideEULAPage>
                <HideLocalAccountScreen>true</HideLocalAccountScreen>
                <HideOEMRegistrationScreen>true</HideOEMRegistrationScreen>
                <HideOnlineAccountScreens>true</HideOnlineAccountScreens>
                <HideWirelessSetupInOOBE>true</HideWirelessSetupInOOBE>
                <ProtectYourPC>3</ProtectYourPC>
            </OOBE>
            <TimeZone>AUS Eastern Standard Time</TimeZone>
            <UserAccounts>
                <AdministratorPassword>
                    <Value>REPLACE-WITH-DEPLOY-PASSWORD</Value>
                    <PlainText>true</PlainText>
                </AdministratorPassword>
            </UserAccounts>
        </component>
    </settings>
</unattend>

    

    
No ComputerName here — each clone gets a random name until Jenkins renames it. No windowsPE pass — sysprep boots never run it. This password is what Jenkins authenticates with.


    
3 Packer template (hyperv-iso, Gen 2)

    

      

packer {
  required_plugins {
    hyperv = { version = ">= 1.1.0", source = "github.com/hashicorp/hyperv" }
  }
}

variable "admin_password" { type = string, sensitive = true }

source "hyperv-iso" "golden" {
  iso_url          = "./iso/ws2022.iso"
  iso_checksum     = "sha256:REPLACE"
  generation       = 2
  switch_name      = "PackerSwitch"
  cpus             = 4
  memory           = 8192
  disk_size        = 61440
  vm_name          = "ws2022-std-golden"            # names the VM and the VHDX
  output_directory = "D:/Templates/ws2022-std-{{timestamp}}"
  cd_files         = ["./autounattend.xml"]
  boot_wait        = "1s"
  boot_command     = ["<enter>"]   # answers "Press any key to boot from DVD"

  communicator     = "winrm"
  winrm_username   = "Administrator"
  winrm_password   = var.admin_password
  winrm_timeout    = "4h"

  shutdown_command = "C:\\Windows\\System32\\Sysprep\\sysprep.exe /generalize /oobe /quiet /shutdown /unattend:C:\\Windows\\Temp\\deploy-unattend.xml"
  shutdown_timeout = "30m"
}

build {
  sources = ["source.hyperv-iso.golden"]

  provisioner "file" {
    source      = "./deploy-unattend.xml"
    destination = "C:\\Windows\\Temp\\deploy-unattend.xml"
  }

  # your provisioners here: Windows updates, agents, hardening ...
}

    

    
The file provisioner uploads the deploy unattend over WinRM so sysprep can find it. Keep shutdown_timeout generous — sysprep on a patched image is slow, and an early give-up leaves a half-generalized artifact.


    
4 Build, name & protect the template

    

      

packer build -var "admin_password=$env:PACKER_ADMIN_PW" .

    

    
The golden image is just a VHDX — nothing inside it depends on the filename, so your naming convention is
    what identifies it. Name it at build time (vm_name / output_directory in the template
    above), or rename it afterwards — safe for a fresh template, because nothing references its path yet:

    

      

# find the VHDX packer just built — the output folder name contains a
# timestamp, so discover it instead of guessing the path
$built = Get-ChildItem "D:\Templates\ws2022-std-*\Virtual Hard Disks\*.vhdx" |
         Sort-Object LastWriteTime -Descending | Select-Object -First 1

# move it into the templates root with a versioned name
# (one folder = the contract: if it lives in D:\Templates, it's a golden image)
$gold = "D:\Templates\ws2022-std-golden-$(Get-Date -Format 'yyyy.MM.dd').vhdx"
Move-Item $built.FullName $gold

# clean up packer's now-empty output folder (leftover exported VM config)
Remove-Item $built.Directory.Parent.FullName -Recurse -Force

# insurance: nobody boots or edits the master (clone jobs Copy-Item from it)
Set-ItemProperty $gold -Name IsReadOnly -Value $true

# optional: checksum + build metadata beside it for later audits
Get-FileHash $gold -Algorithm SHA256 | ConvertTo-Json |
    Set-Content ($gold -replace '\.vhdx$', '.json')

    

    
Prefer determinism over discovery? Have Jenkins pass its build number into the template —
    output_directory = "D:/Templates/build-${var.build_id}" — and the path is known exactly, no glob needed.

    
    
      
  • Never boot the template after sysprep — the first boot consumes the generalized state. Clone the VHDX; the read-only bit keeps it honest.
    • 
      
  • Version with a date or build number so you can roll back a bad image — the clone job just picks the newest file matching the pattern.
    • 
      
  • Only rename a VHDX nothing references yet — a VM config or differencing disk pointing at the old path would break.
    • 
      
  • Rebuild rather than re-sysprep repeatedly — sysprep has a limited rearm count.
    • 
    


    
5 Clone, rename, join (Jenkins)

    
Clones boot straight to the logon screen with WinRM listening. From the Hyper-V host (or a Jenkins agent on it):

    

      

# $vmName is the Hyper-V VM object name YOU chose at New-VM/clone time —
# not the guest's random Windows hostname. The IP is read via Integration
# Services (KVP), so DNS and the hostname are never involved.
# Tip: name the VM after the final hostname so $vmName doubles as -NewName.
do {
    Start-Sleep -Seconds 5
    $ip = (Get-VMNetworkAdapter -VMName $vmName).IPAddresses |
          Where-Object { $_ -match '^\d+\.' -and $_ -notmatch '^169\.254\.' } |
          Select-Object -First 1
} until ($ip)

$loc = New-Object PSCredential('Administrator',
       (ConvertTo-SecureString $env:LOCAL_ADMIN_PW -AsPlainText -Force))

Invoke-Command -ComputerName $ip -Credential $loc -Authentication Negotiate -ScriptBlock {
    $join = New-Object PSCredential($using:joinUser,
            (ConvertTo-SecureString $using:joinPw -AsPlainText -Force))
    Add-Computer -DomainName corp.example.com -NewName $using:newName `
                 -OUPath 'OU=Servers,DC=corp,DC=example,DC=com' `
                 -Credential $join -Restart
}

    

    
-NewName renames and joins in one operation — one reboot, and the AD object is created with the final name. Use the built-in Administrator: other local admins get a filtered token over WinRM unless LocalAccountTokenFilterPolicy is set.


    
Security notes

    
    
      
  • The WinRM bootstrap allows Basic + unencrypted HTTP — fine on an isolated build network, but it persists into clones. To harden, add a final provisioner before sysprep: winrm set winrm/config/service @{AllowUnencrypted="false"} and disable Basic — Jenkins still works via -Authentication Negotiate (NTLM encrypts over HTTP).
    • 
      
  • Passwords in both XMLs are at best Base64-obfuscated. Keep generated files out of the public repo; template the real password in from Packer variables / Jenkins credentials.
    • 
      
  • After domain join, rotate or disable the local Administrator (GPO/LAPS) — it's a bootstrap credential only.
